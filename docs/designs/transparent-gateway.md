# 透明 HTTP 设计边界

早期草案已由 2.1 的独立透明入口替代。当前配置和授权契约以[透明转发说明](../transparent-forwarding-proposal.md)为准。

原生协议负责明确的请求结构、模型授权、响应解析和用量提取。透明入口 `/proxy/{group_id}/*path` 只转发管理员固定上游中的显式授权路径，保留请求与响应内容，不推断未知正文的模型、任务类型或计量单位。

两种入口复用现有快照、凭据池、健康状态和调度器。透明授权默认关闭，需要独立协议许可及分组、方法、路径范围。模型白名单与金额预算不能用于未经解析的透明正文。

独立请求可以轮换凭据。有状态协议需要固定凭据，来源不可用时返回失败。固定凭据只保证选中同一来源，不会自动改写供应商 URL，也不代表未知异步协议的整个生命周期已实现。

透明请求每次只尝试一次。HTTP 429、连接错误或 5xx 都不能证明上游尚未接受任务，因此不会自动重发。已实现的原生操作继续按各自的重放契约处理。

OAuth 刷新、Vertex 服务账号和 Bedrock 签名继续使用专用适配。首版透明入口仅适用于静态单字段 API key，不支持 WebSocket 或任意目标主机。
