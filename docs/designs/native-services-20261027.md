# 原生服务设计

设计核验日期为 2026-10-27。实现沿用 Go、Gin、GORM、Bifrost 与 Vue，保留 API-Load 品牌、图标、既有数据和调用 ID。部署流程见[通用运维指南](../operations.md)。

## 需要解决的问题

| 问题 | 实现方向 |
| --- | --- |
| Cohere 预设原先只声明文字重排，兼容 Embeddings 入口限制图片输入 | 增加独立 `/v2/embed` 原生入口，保留 texts、images、inputs 和供应商参数 |
| SiliconFlow 的结构化检索输入无法通过纯文字 SDK 预检 | 单独处理原生 Embedding/Rerank，分别描述查询与候选的模态 |
| Vertex Embedding 需要项目、区域和服务账号鉴权 | 保留原生 publisher 路径及 inlineData，不当作静态 API key 服务 |
| 文件和异步任务的后续操作可能选中另一把凭据 | 记录资源归属，后续操作回到原创建凭据，并检查访问令牌归属 |
| 模型说明被当成当前账号已经可用 | 分开模型规格、供应商开放范围、实现路径和有限期验证记录 |
| 非 token 用量被忽略或写成零 | 分别保存供应商报告的页数、图片、时长及搜索单位，缺失值保持未知 |

## 协议边界

有原生实现的接口保留原始语义。格式转换只能使用可表达的字段；无法保留重要图片、工具或思考参数时，应明确拒绝，不能返回成功后静默丢弃。

OCR、语音、文件、视频和专用决策协议具有独立请求与响应结构。文件上传、任务创建、查询、下载和取消分别接入，供应商没有提供的操作不虚构统一接口。

## 调度与资源

继续复用分组优先级、组内权重、软粘性、RPM、并发和冷却。相同账号的多把 key 不表示多份额度，共享账号标识由管理员设置。余额驱动调度只能采用可靠的供应商观测，参数错误不应轮换全部凭据。

文件和任务的后续请求检查访问令牌、凭据身份与资源归属。归属缺失或固定来源不可用时明确拒绝；任务可能被接受或流式响应已经开始后，不自动重放。

## 数据与兼容

新用量及证据字段采用可空 JSON 列，旧数据不补造测量值。既有访问令牌默认不获得新增资源权限，原生接口与透明 HTTP 的授权分开处理。

所有迁移先在副本上审查和验证。恢复保留原数据库、加密材料及镜像，不创建空库代替历史数据。具体接口、验证边界和未完成范围见[原生服务说明](../native-services-20261027.md)。
