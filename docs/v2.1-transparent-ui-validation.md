# 2.1 透明转发界面验收

2026-10-28 在隔离实例完成界面检查，使用合成凭据、访问令牌、来源和本机模拟上游。检查涵盖候选程序与页面，没有调用真实供应商或修改现有客户端。下列结果只表示所列流程已操作和回读，不代表生产或全部设备验收。

通过 CUA 浏览器实际操作、重新打开表单和截图检查，覆盖了下列行为。

| 操作 | 观察结果 |
| --- | --- |
| 新建 `transparent_http` 来源，录入两条合成凭据，不添加模型 | 创建成功，模型数保持 0；未开启前显示“未启用透明转发” |
| 高级配置开启透明入口，设置含 `/service` 前缀的上游 URL | 保存成功，主界面显示独立客户端地址 `/proxy/3` |
| 选择固定凭据 | 下拉显示掩码与编号，保存并重新打开后恢复同一条凭据；没有复制原始 key |
| 复制客户端 Base URL | 剪贴板内容与页面显示的 `http://127.0.0.1:18364/proxy/3` 一致 |
| 查看服务与验证 | 显示透明模式、实际支持的七种 HTTP 方法、原始请求体和原始响应；模型数为 0 时说明无需配置模型 |
| 新建访问令牌 | 透明授权默认关闭 |
| 编辑已有令牌，仅增加透明授权 | 显式指定 `transparent-http`、分组、POST 和 `/v2/embed` 精确路径后保存成功，重新打开后范围保留 |
| 仅修改已授权路径 | 从 `/v2/embed` 改为 `/v2/rerank` 后保存成功，重新打开后显示新路径 |
| 撤销透明授权 | 只关闭透明开关即可保存；重新打开后开关保持关闭，列表授权标记消失 |
| 不选择任何组、方法或路径 | 表单给出具体缺失提示，不能保存空授权 |
| 协议选择“全部”，同时开启透明授权 | 最终界面提示必须在协议范围中加入 `transparent-http`；不会把空协议列表解释成透明授权 |
| 已有透明授权时添加费用额度 | 表单说明透明请求不解析费用，要求移除费用额度或关闭透明授权 |
| 最终创建表单与服务卡 | 专用透明预设不显示模型输入区；方法和路径分行显示，图标采用现有 HTTP 文本回退 |

新增与修改授权都观察到了真实保存结果，随后重新读取服务器状态。保存代码还通过 Vite SSR 加载实际 TypeScript 模块检查，覆盖默认拒绝、单独增加/修改/删除 `transparent` 时生成补丁、方法顺序不产生无意义补丁、深复制不修改原数据，以及 `allow_model_less_resources` 从 true 关闭时仍生成补丁。经典界面的保存代码同样验证了嵌套透明授权和共享账号限制的保留。

运行过 `vue-tsc`、Node TypeScript 检查、全量 ESLint、现有现代样式检查和 Vite 生产构建。最终两处显示修改另跑了对应 ESLint、样式检查与构建。构建产物由真实 Go 程序加载，健康接口返回 `2.1.0`。

浏览器验收中发现并修复了三项问题。透明路由最初进入旧供应商适配器校验，导致容器构造失败；现在由网关负责执行。固定来源保存时，局部分组校验缺少本组凭据元数据；现在校验读取所需元数据。前端最初允许空协议列表，而后端要求显式 `transparent-http`；现在表单提前解释这个要求。相应修复位于 `internal/provideradapter/registry.go`、`internal/control/group_update.go` 和 `web/src/shared/transparent.ts`。
