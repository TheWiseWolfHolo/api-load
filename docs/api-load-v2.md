# API-Load v2

本分支从 GPT-Load `v2.0.0-rc.45` 开始，提交 `a5c691bb0559f856ebb587879d82e341ff480202`。该提交在 2026-10-07 核验时也是上游 main。

API-Load 保留自己的名字和图标，镜像发布到 `ghcr.io/thewisewolfholo/api-load`。上游的许可证、版权和第三方声明完整保留。Go 模块路径及内部包沿用上游，方便后续合并更新。

`2.0.0-apiload.4` 接入上游 PR #830 的自定义错误规则及两条修复，来源提交为 `e479aefc5e337266240d11449f3df1a0fb2d9b0c`。全局设置与分组高级设置都可编辑规则，默认规则为空。状态码与错误关键词决定重试、模型或凭据冷却、失败计数及跳过分组；认证和请求重放约束继续生效。此功能不执行批量密钥探测。

新版界面的分组模型同步支持选择新增项、填写公开名称、处理上游未返回项，以及更换上游模型并保留原公开名称。默认不新增或删除模型，目录建议不会当作实时上游模型。确认后先进入编辑草稿，再保存；取消草稿不写入服务器。新增撞名与重复映射会阻止应用，已有多来源映射继续保留。

模型保存请求可以携带 `expected_models`。服务器在写入事务中核对已有映射，配置已变化时返回 `GROUP_MODELS_CHANGED`，避免旧草稿覆盖更新。旧客户端不携带此字段时沿用既有保存行为。上游模型替换后，价格按新模型身份解析；公开名称保持不变不代表价格和能力相同。

用户已授权发布 `2.0.0-apiload.2` 候选镜像。代码继续在 `feat/gpt-load-v2-adoption` 分支维护，main 合并另行安排。已发布标签 `v2.0.0-apiload.1` 保持原提交。

新版部署到 Tencent US，访问地址为 `https://apiload.wolfholo.com`。New API 渠道使用 v2 统一入口及各分组专用访问凭据。

迁移使用独立数据库。旧 Key、备注和启用状态转换为 v2 凭据，旧失效或冷却中的 Key 先禁用。共享资源池展开到各分组，之后由 v2 分别管理。模型列表和可对应的别名迁入 v2。旧请求统计、日志、配置和其它表随原始数据库备份保留。

上线前必须核对备份、源数据数量、目标数据数量、管理端登录和下游调用。旧实例及数据库保留到新版本确认稳定。切换后产生的新数据需另行处理，不能直接切回旧库。

此版本增加了[按次价格](per-request-pricing.md)，支持成功请求按固定金额计费，并记录费用回执、成本统计与访问密钥额度。发布工作流会先在 Linux 上检查定价、迁移、日志、配额和网关，再构建镜像。
