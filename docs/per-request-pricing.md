# 按次价格

模型价格可选择 token 计费或按次计费。按次价格使用 USD/request，成功请求收取一次费用，并应用分组与访问密钥的价格倍率。上游未返回 token 用量时，成功请求仍可计费。

HTTP 错误、上游错误、取消请求和未完整结束的流式请求不收取按次费用。流式请求只有正常结束时才计费。重试过程只结算最终成功请求。

## 配置

在模型详情中打开价格编辑器，选择按次计费并填写每次价格。`0` 表示免费，空值表示尚未定价。按次价格不能同时设置 token 价格、上下文阶梯或服务模式价格。

管理接口 `PUT /api/model-prices/{id}` 接受以下字段。

```json
{
  "billing_unit": "request",
  "request_price": "0.0025",
  "input": null,
  "output": null,
  "cache_read": null,
  "cache_write": null,
  "context_tiers": [],
  "mode_schedules": {}
}
```

价格按渠道和实际上游模型 ID 保存。同一个上游模型的多个客户端别名共享这份价格。需要按别名设置不同售价时，可在 New API 中分别设置。

## 日志和配额

按次费用写入请求日志、成本统计与访问密钥额度。日志保留上游实际返回的 token 用量；没有 token 用量时仍显示按次金额。费用回执使用版本 7 和 `fixed_per_request` 方法，包含请求数量、单次价格及倍率。历史 token 回执继续按原格式读取。

## 升级

迁移 `0030_model_request_prices` 为模型价格和请求日志补充计费单位，原有记录默认使用 token 计费。SQLite 迁移保留请求日志的子记录、索引和触发器。升级前应备份数据库，在生产所用数据库副本上演练迁移，再启动新服务。

本候选改动已通过 SQLite 迁移与重复执行检查、定价和日志测试、网关配额检查，以及两套前端的 lint、类型检查和构建。2026-10-07 使用生产 PostgreSQL 副本演练升级，从 29 次迁移升到 30 次，24 张表的既有数据指纹一致，重复迁移与按次费用写入检查通过。MySQL 迁移尚未在真实服务上演练。
