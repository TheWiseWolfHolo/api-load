# 2.2.4 恢复文件容错

2.2.3 复核中发现，`resource-bindings.pending.json` 一旦无法解析，恢复过程会在读取主 checkpoint 前返回。坏文件留在原位，每次启动都会重复失败，正常的冷却、统计和调度状态也无法恢复。

2.2.4 将坏文件改名留存于同一运行目录，然后继续恢复有效的主 checkpoint。解析失败仍返回给原有生命周期日志，不会报告为完全成功。下一次启动不再重复处理已留存的坏文件；重命名失败时明确报错并保留原文件。

此修复不尝试猜测损坏内容，不删除留底文件，也不重新创建上游任务。资源导入仍共用三秒预算，数据库暂时失败的有效记录继续等待下次启动处理。逐条给予三秒可能随记录数显著增加启动耗时，本轮不改动该约束。

数据库结构继续使用迁移0033。恢复回归覆盖损坏pending与有效主checkpoint共存、坏文件内容保留、再次启动及重命名失败。MySQL并发语义仍未实测，2.2.3的SQLite和PostgreSQL验证范围保持原记录。
