# 2.2.3 一致性修复

2026-10-29 复核 2.2.2 的资源归属持久化、共享账号限流、错误识别和管理端数据契约。沿用现有架构，保留模型 ID、凭据、价格与下游接口。本次不新增数据库迁移，继续使用 0033。

## 资源归属

2.2.2 的唯一键冲突使用 DoNothing，数据库拒绝写入后仍向调用方返回成功。内存未命中时登记另一把凭据，可能在重启前后得到不同归属。过期旧行还会阻止同 ID 的新记录写入，随后旧行被清理，造成资源缺少持久归属。

修复后由数据库在事务中确认有效归属，明确拒绝不同凭据或身份版本的冲突；已过期记录可重新登记。数据库返回实际归属及到期时间，缓存保留这些值，不因回查或重复登记延长寿命。不同下游令牌仍分别隔离。

数据库写入暂时失败时保留既有的内存回退和诊断日志，避免隐藏已经被上游接受的资源。这个状态仍可能在异常退出后丢失归属，不能描述为持久化成功；数据库查询失败继续明确报错。请求已被接受后不会为了保存归属而重新创建上游任务。

## 恢复、限流和发布

恢复运行目录时，将尚未落库的资源归属保留为独立待导入文件。失败后可以继续导入，不重复恢复旧的统计、冷却等运行状态。

共享账号 RPM 窗口的清理移到公共准入入口。账号池被移除、后续只剩普通分组请求时，过期窗口也能回收；仍保持每分钟最多一次清理，完全无流量时等待下一次请求。

main 镜像使用 `edge` 和 `v2-sha-<commit>`。正式发布使用版本标签及 `v<version>-sha-<commit>`，只有稳定版本更新 `2`。两种运行版本不会再竞争同一个提交标签。已经发布的历史标签不删除或重写。

OpenRouter 原生 Chat 流在 HTTP 200 之后仅返回数字 `code=429` 时，现在也按模型限流记录。此前补丁覆盖了转换路径，原生流的末尾错误解析仍遗漏此情况。修复保留已经输出的内容、上游请求标识与原始 SSE，提交响应后不重新生成。

## 审查范围与验证边界

批量价格的按次金额、零与未知值、引用关系及服务能力字段完成源码契约核对，没有因此改动界面。现有 OpenRouter generation ID 与转换路径数字 429 识别修复保留。

回归重点覆盖资源冲突、过期后重新登记、缓存回填、数据库故障、恢复重试，以及普通分组流量下的过期 RPM 窗口。合成测试不调用真实模型，不上传私人资料。部署继续先检查生产数据库副本，再备份并替换镜像。上线验证读取健康接口、管理 API 和数据指纹，不把历史模型请求当作本次验证。

持久化用例实际运行于 SQLite 与隔离 PostgreSQL 17，包括并发争用同一资源的情况。MySQL 本轮没有外部数据库实测。界面核对为源码检查，未重新执行整套浏览器操作。
