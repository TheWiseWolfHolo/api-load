## 价格操作

在模型页面打开批量价格设置，选择目标和维护方式。

- 复制会保存独立价格，之后修改来源不会改变复制目标。直接输入价格也使用这个方式。
- 引用会保留来源关系。来源金额、计价单位、缓存价格、阶梯或模式价格变化时，关联模型在同一事务内更新。手动编辑关联模型会解除它自己的引用，其他模型的关系继续保留。

提交前可以查看来源、目标和受影响分组。每次最多设置 100 条价格。服务器拒绝循环引用，不允许删除仍被引用的来源；写入失败会撤销整个批次。引用只改变费用估算，不改变模型调用 ID、模型映射或上游服务。

金额 `0` 表示明确免费，`null` 表示未知。按次价格沿用 `billing_unit=request` 与 `request_price`，不换算成 token。缺少上游用量时，token 费用保持未计价；管理员明确配置的按次费用仍按既有规则处理。

管理 API 新增 `GET /api/model-prices/sources` 和 `POST /api/model-prices/batch`。批量请求使用 `ids`、`mode=copy` 与 `price`，或 `ids`、`mode=link` 与 `reference.price_id`。这些管理操作要求管理鉴权，不能使用下游访问令牌。

## 原生 TTS

入口为 `POST /v1/audio/speech`，新令牌可选择 `audio-speech` 协议，再限制可用分组和模型。渠道仍分别选择 OpenRouter 或 Mistral。不要把两个供应商的声线名称与字段混用。

| 渠道 | 上游目标 | 请求与响应 |
| --- | --- | --- |
| OpenRouter | 默认 `https://openrouter.ai/api/v1/audio/speech` | JSON 请求保留 `input`、`voice`、`instructions`、`response_format`、`provider` 及其他供应商字段。成功响应保留二进制音频与 Content-Type |
| Mistral | 默认 `https://api.mistral.ai/v1/audio/speech` | 保留 Mistral 原生请求字段与 JSON/音频响应，沿用已有声线接口 |

网关读取并映射模型名，其他字段按所选上游协议传递。OpenRouter 官方返回格式、声线与多说话人输入要求见[原生 TTS 指南](https://openrouter.ai/docs/guides/overview/multimodal/tts)及[接口定义](https://openrouter.ai/docs/api/api-reference/tts/create-speech)。这些模型参数由供应商决定，网关不会为不支持的模型伪造转换。

OpenRouter 的 `X-Generation-Id` 可作为上游请求标识记录；响应同时提供 `X-Request-Id` 或 `Request-Id` 时保留原有优先级。日志不保存输入文字或音频内容。

已有仅授权 `mistral` 的令牌继续走旧 Mistral 语音路径，其权限不会扩展到 OpenRouter。旧日志中的 `mistral_audio_speech` 仍可读取和筛选；新协议记录为 `audio_speech`。原有分组、模型和速率限制继续生效。

本版按完整响应处理 TTS，不支持 `stream=true`，也不提供低延迟音频分块播放保证。原始 PCM 即使碰巧以压缩魔数开头也不会被误判，真正压缩且无法安全交付的响应会明确失败。上游已接受生成或开始返回内容后，沿用不可安全重放的保护，避免自动重复生成。音频没有可靠用量时保持未知，不根据文件大小推算 token、时长或费用。

## 迁移与恢复

迁移新增 `0032_model_price_reference`，为 `model_prices` 增加可空的 `source_price_id`、索引与自引用外键。已存在的 `0031_usage_units` 保持原编号和内容。旧价格、凭据、令牌与模型 ID 不重建。SQLite 必须重建价格表来增加外键，迁移会复制原列并保留索引、触发器与自增序列；PostgreSQL/MySQL 使用增加列和约束。

升级前按[发布与恢复指南](operations.md)备份数据库、加密材料和程序版本，在隔离副本上验证。不要在旧程序和新程序间交替写入同一个已升级数据库。需要恢复时，停止写入并保存失败状态，恢复升级前数据库及匹配的程序与加密材料，再核对凭据解密和原令牌。升级后产生的数据应另行保留，不能用旧备份直接覆盖后还声称没有损失。

`scripts/verify-native-container.py` 使用已有本地镜像、隔离 Docker 网络和合成 PostgreSQL 数据，检查旧凭据解密、原令牌、按次价格迁移、引用传播、复制独立性、零与未知值，以及重启后的持久化。它不访问真实供应商，不替代生产数据库副本验收或音频质量验证。

TTS 测试使用合成上游，覆盖路径与鉴权、模型映射、原生字段、JSON/二进制音频以及旧令牌权限隔离。合成音频不能证明真实声线质量，也不能证明某个账号拥有指定型号。真实供应商验证应另外限制型号、次数和成本。

## 本次验证范围

- 新版界面已在隔离 SQLite 实例中实际保存复制、引用、来源更新和解除引用，并核对持久化结果。零价格与未知价格分别展示。经典界面完成类型、lint 和摘要渲染检查，未完整重走浏览器保存流程。
- PostgreSQL 17 使用合成数据从 2.1.1 升到 2.2.1，旧凭据解密、原访问令牌、按次价格和使用量列均保留；引用更新、独立复制、零与未知值及重启检查通过。SQLite 迁移回归通过，MySQL 本轮未执行外部数据库实测。
- 前端类型、lint、格式和生产构建，以及 Go vet 均通过。协议、价格、迁移、遥测和音频权限检查使用本地合成上游。PCM 包含 JSON 形状时也经过逐字节保持检查。

上述结果不包含生产数据副本迁移、线上替换或真实 TTS 音质验收。
