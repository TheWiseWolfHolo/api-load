2026-10-28 对 `tbphp/gpt-load` 执行 fetch，当前上游 main 为 `44814181b44e2bee76c6bb79751b8d2b6b9ec350`。评估按现有实现逐项选择，不整批合并上游；Go 模块路径、品牌、图标和运行框架保持兼容。

## 发布中发现的问题

原 `VERSION` 为 2.0.5，README 标记仍指向 2.0.1 和旧 candidate 镜像。本地发版脚本仍查询 `tbphp/gpt-load`，升级测试也使用上游镜像；候选构建固定写成 2.0.0-preflight。tag 建议只递增上一版 patch，可能先推送一个与 VERSION 不符的 tag，然后才在 CI 失败。

发布工作流原先还会让任意 v* 标签更新稳定 `2` 通道，包括 rc 标签。本轮分开候选版、不可变提交镜像和稳定通道，并在创建 tag 前检查 VERSION。

## 2.1 命名

| 用途 | 名称与约束 |
| --- | --- |
| 当前源码 | `VERSION=2.1.2`，候选尚不表示镜像已发布 |
| 隔离检查阶段 | 使用过 `2.1.0-rc.1`，没有发布该标签 |
| 正式发布标签 | `v2.1.2`，须与源码 VERSION 匹配且通过该提交的验收 |
| 镜像仓库 | `ghcr.io/thewisewolfholo/api-load` |
| 正式镜像 | `:v2.1.2`，发布后才存在 |
| 可追溯构建 | `:v2.1.2-sha-<short-commit>`，另保留旧 `:v2-sha-<short-commit>` 别名 |
| 稳定通道 | `:2`，只由无预发布后缀的正式标签更新 |
| main 构建 | `:edge`，程序版本附加 edge 和提交号 |

镜像标签不改变数据库身份或访问令牌。生产应固定版本标签或 image digest；切换候选版不更新日常客户端模型选择，也不改原有公开模型 ID。

本地 `make build`、`make run` 与 Docker 默认构建读取 VERSION，显式 Docker VERSION 构建参数仍保留。发版 CLI 查询 API-Load 的发布工作流和上一版本镜像，按实际支持的 linux/amd64 核验 revision，不再要求上游多架构镜像或不存在的 GitHub Release 对象。

默认验收仍包括三数据库、Compose、合成流式请求和界面。依赖外部配置的 mini 验收改为显式 `--with-mini`，默认不读取该环境或发送真实模型请求。未启用时报告写明 `external_mini=not_requested`。生产数据副本迁移、账号实测和部署恢复仍须单独完成，不能把本地测试通过写成生产验收完成。

本轮只修改发版规则和文档，没有创建、推送 tag 或触发镜像发布。
